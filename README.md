# KafMind 🧠⚡

KafMind is an enterprise-grade, ChatGPT-like **Agentic RAG** (Retrieval-Augmented Generation) application designed for high-speed document retrieval, autonomous agent reasoning, and scalable, asynchronous file ingestion powered by **Apache Kafka**.

---

## 🚀 Key Features

- **Asynchronous File Ingestion**: File uploads return `202 Accepted` immediately without blocking the client. File parsing, chunking, and vector indexing run asynchronously through event streams on Apache Kafka.
- **Agentic RAG Reasoning**: LangGraph orchestrates multi-step retrieval, query routing, source evaluation, and synthesis loops.
- **Streaming Responses**: Token-by-token real-time streaming directly to the client via Server-Sent Events (SSE).
- **Strict Multi-Tenant Isolation**: Every vector embedding payload stored in Qdrant is isolated with mandatory `user_id` filters.
- **Modern Responsive UI**: Built with React 19, TypeScript, TailwindCSS, and shadcn/ui for a fluid, ChatGPT-like conversation experience.

## 📐 System Architecture & Workflows

### 1. Asynchronous File Upload & Kafka Ingestion Pipeline
When a user uploads a document, FastAPI persists the raw file and initial metadata, emits an event to Kafka, and immediately responds to the client. The ingestion worker processes and embeds chunks asynchronously, reporting progress over Redis pub/sub.

```mermaid
sequenceDiagram
    autonumber
    actor User as Client / Frontend
    participant API as FastAPI Backend
    participant Storage as File Storage / Disk
    participant PG as PostgreSQL
    participant Kafka as Apache Kafka (KRaft)
    participant Consumer as Ingestion Consumer
    participant FastEmbed as FastEmbed (BAAI/bge-small-en-v1.5)
    participant Qdrant as Qdrant Vector DB
    participant Redis as Redis Pub/Sub

    User->>API: POST /api/v1/files/upload (multipart/form-data)
    API->>Storage: Save file to disk
    API->>PG: Insert File Record (status: PENDING)
    API->>Kafka: Publish event to topic `file.uploaded`
    API-->>User: HTTP 202 Accepted {file_id, status: "PENDING"}

    Kafka->>Consumer: Consume event `file.uploaded`
    Consumer->>Redis: Publish status update (status: PROCESSING)
    Consumer->>Storage: Read file content
    Consumer->>Consumer: Extract text & chunk text
    Consumer->>FastEmbed: Generate embeddings (384-d)
    FastEmbed-->>Consumer: Vector embeddings
    Consumer->>Qdrant: Upsert vectors with payload {user_id, file_id, text, metadata}
    Consumer->>PG: Update File Record (status: COMPLETED)
    Consumer->>Redis: Publish status update (status: COMPLETED)
    Redis-->>User: Real-time status update via SSE / PubSub
```

### 2. Agentic RAG & SSE Streaming Flow with LangGraph
User questions flow through a LangGraph agent loop. The agent evaluates whether contextual retrieval is required, queries Qdrant with tenant-isolated filters, and streams tokens generated by DeepSeek V4.1 Flash via Server-Sent Events (SSE).

```mermaid
flowchart TD
    User([User / Client UI]) -->|Prompt & Chat History| API[FastAPI SSE Endpoint]
    API -->|Initialize Graph State| LangGraph[LangGraph Agent Controller]
    
    subgraph Agentic_RAG_Flow [LangGraph Agentic Decision Loop]
        LangGraph --> Router{Agent Query Router}
        Router -->|Direct Answer / General Query| LLMNode[LLM Generation Node]
        Router -->|Retrieval Needed| RetrieveNode[Document Retrieval Node]
        
        RetrieveNode --> EmbedQuery[FastEmbed: Embed Query Vector]
        EmbedQuery --> QdrantSearch[Qdrant Search with user_id Filter]
        QdrantSearch --> ContextAggregator[Format & Filter Document Context]
        ContextAggregator --> LLMNode
    end
    
    LLMNode -->|Streaming Request via ChatOpenAI| TokenHarbor[Token Harbor: DeepSeek V4.1 Flash]
    TokenHarbor -->|Token Stream Tokens| LangGraph
    LangGraph -->|Yield SSE Events chunk-by-chunk| API
    API -->|text/event-stream| User
```

## ⚡ Quick-Start Instructions

### Prerequisites
- Python 3.12+ (or Conda environment `ml-env`)
- Node.js 20+ & npm / pnpm
- Docker & Docker Compose (for PostgreSQL, Redis, Kafka, and Qdrant)

### 1. Environment Configuration
Copy the sample environment file and configure your API keys:
```bash
cp .env.example .env
```
Ensure `TOKEN_HARBOR_API_KEY` is provided in `.env`.

### 2. Infrastructure Services (Docker)
Start the supporting services (PostgreSQL, Redis, Qdrant, Apache Kafka):
```bash
docker compose up -d
```

### 3. Backend Setup
Activate your Python environment and start the FastAPI service:
```bash
conda activate ml-env
cd backend
pip install -r requirements.txt
alembic upgrade head
uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

In a separate terminal, launch the Kafka ingestion consumer:
```bash
conda activate ml-env
cd backend
python -m app.workers.kafka_consumer
```

### 4. Frontend Setup
Install dependencies and run the Vite development server:
```bash
cd frontend
npm install
npm run dev
```
Open [http://localhost:5173](http://localhost:5173) in your browser.
